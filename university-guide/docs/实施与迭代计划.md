# 实施与迭代计划

本站作为独立发布包实施，不修改、不推送上游 `Crys-Chen/ic-guide`，也不代表上游维护者认可。

## 已完成的五个阶段

| 阶段 | 已实施内容 | 可验证输出 |
|---|---|---|
| 1. 现站盘点 | 固定上游 commit，统计页面、导航、课程、骨架、方向、重定向和重复内容 | `现站审计.md`、`upstream-inventory.json` |
| 2. 培养体系 | 整理 32 个公共能力建议 + 24 个专业能力建议，构建无环先修图、五个可移动建议窗口与六路线 | 能力、路线 YAML |
| 3. 资源编辑 | 为 56 能力各选主/备两项，记录章节、时长、练习、分项评分与核验日期 | 112 条视频 YAML、资源索引 |
| 4. 站点与映射 | 生成 56 能力页、6 路线页、自由探索路线、复旦 2025 映射及可搜索/可筛选索引 | MkDocs 源码与静态 `site/` |
| 5. 质量门槛 | 校验依赖、资源质量、评分、映射、生成漂移、构建、内链与内容抽查 | 校验脚本与 `reports/` |

## 发布流程

1. 只修改 `data/*.yml` 和手写指南，然后运行 `scripts/render.py`。
2. 执行 `validate.py --strict`、`render.py --check`、`mkdocs build --strict`、`check_site.py`。
3. 在能联网的环境执行 `check_links.py --strict`，处理所有失败或人工复核项。
4. 六路线各抽两个能力，对照官方逐讲目录；不能只根据课程名判定。
5. 本地启动 `mkdocs serve`，以桌面和窄屏视口确认搜索、组合筛选、计数、重置和表格滚动。
6. 将站点目录发布到 GitHub Pages 或任意静态托管；本包不预设域名。

## 上游合并顺序

若上游维护者愿意吸收改进，建议拆成可独立审核的四组：

1. 先修复两个 `on_post_build` 覆盖和 CI 缺脚本，补严格构建/内链门槛。
2. 引入自动盘点，用可复现的 60 个骨架、11 个待建页代替 README 手工数字。
3. 扩展课程模板的能力成果、建议窗口、资源评分和复核日期。
4. 再逐步引入能力/资源数据和筛选索引，不要将整个独立站点作为一个巨型补丁。

## 维护节奏

- 每 6 个月：复核 112 条链接、章节、语言/字幕和资源角色。
- 每年：重新抽查六路线、复核 17 方向和岗位/升学出口。
- 学校发布新版培养方案后：保留旧年份映射，新增年份而不覆盖历史证据。
- 每次发布：运行全部五道质量门槛，更新验收报告与校验日期。
