# IC Guide 上游可合并改进包

目标仓库：[Crys-Chen/ic-guide](https://github.com/Crys-Chen/ic-guide)  
依据快照：`ec90dfde5c36e89461386547903c7caaff107436`  
约束：本文只提供可执行补丁设计，不修改、不提交上游仓库。

## 实施原则

- 每个 PR 只解决一类问题，先恢复构建可信度，再迁移内容数据。
- 所有数字从源码生成；README 不再人工维护课程、骨架或待建数量。
- 现有 URL 尽量不变。页面数据化时继续生成原路径，已有 263 条 redirect 不扩大。
- 视频、教授、企业、就业等会过时的信息必须带来源和核验日期。
- CI 先检查确定性的内部一致性；外部链接先做定时报告，稳定后再提升为合并门禁。

## PR 1：修复构建 hook，并为两个副作用加回归测试

### 问题

`hooks.py` 在第 143 行和第 212 行两次定义 `on_post_build`。虽然第 209 行保存了第一次定义为 `_orig_on_post_build`，第二次定义没有调用它。结果是 pending CSS 会生成，而中文 `search_index.json` 修补不会从 hook 入口执行。

### 最小补丁

先做无行为争议的最小修复：

```diff
 def on_post_build(config, **kwargs):  # noqa: F811
+    _orig_on_post_build(config, **kwargs)
     _write_pending_css(config)
```

随后在同一 PR 内把命名改清楚，消除再次覆盖的可能：

```python
def _patch_material_search_index(config):
    ...

def on_post_build(config, **kwargs):
    _patch_material_search_index(config)
    _write_pending_css(config)
```

不要保留 `_orig_on_post_build` 这种依赖定义顺序的别名。

### 搜索架构决策

生产页头和 CI 已明确使用 PageFind，Material/Lunr 索引只是潜在回退。该 PR 先恢复既有意图，不同时重写搜索。下一版确认 PageFind 中文搜索覆盖率后，推荐删除 Material 搜索索引修补、jieba 词表以及相关死代码，只保留 pending CSS hook，形成单一搜索后端。

### 测试

新增 `tests/test_hooks.py`：

1. 在临时 `site/search/search_index.json` 写入含零宽空格的中文文本，调用 `on_post_build`，断言 n-gram 被写回。
2. 在临时 `docs` 写一页 `# 〔待建〕`，调用 `on_post_build`，断言 `site/stylesheets/pending.css` 生成对应选择器。
3. 搜索索引不存在时，pending CSS 仍生成且不报错。
4. 没有 pending 页面时，CSS 文件仍存在、内容只有生成注释。

### 完成定义

- 两项输出在同一次 hook 中都被验证。
- `mkdocs build --strict` 通过。
- 不改变页面 URL 或导航。

## PR 2：移除失效的股票行情子系统和小时级部署

### 决策

直接移除股票行情，而不是补写 `fetch_foreign_quotes.py`。教育指南的企业信息需要官网与岗位说明，不需要实时股价；行情造成小时级写权限、第三方行情依赖和持续维护，却不改善学习决策。

### 改动

- 删除 `.github/workflows/ci.yml` 的 `schedule`、`fetch_foreign_quotes.py` 调用及相关注释。
- 删除 `docs/javascripts/stock-quote.js`，并从 `mkdocs.yml` 的 `extra_javascript` 移除。
- 在 17 个方向页中删除 164 个 `.sq` 行情 span，保留企业官网链接和企业名称。
- 不新增 `quotes.json`，也不保留静默回退逻辑。

当前有 13 个 `yf:` span、11 个海外代码会直接受缺失脚本影响；其他行情也依赖客户端第三方接口。统一移除比只补海外脚本更一致。

### 测试

```bash
rg 'data-stock=|stock-quote|quotes.json|fetch_foreign_quotes' .
```

应无结果；正常 push 和手动触发仍能部署。

### 完成定义

- CI 不再引用不存在的文件，也没有 `|| true` 隐藏预期功能失败。
- workflow 不再为行情每小时重建并写 `gh-pages`。
- 企业官网入口仍完整。

## PR 3：把内容状态统计改为生成物

### 问题

真实骨架为 60 个；README 列了 85 个，其中 26 个已经不再是骨架，另有 1 个骨架未列。`# 〔待建〕` 有 11 处，但“没有子课程页”的栏目只有 5 个，而且类脑与 SNN 已有替代资源。

### 数据定义

生成脚本必须只依赖可复现标记：

```yaml
skeleton_course:
  predicate: contains('!!! note "待补充"')
pending_slot:
  predicate: first_h1_starts_with('# 〔待建〕')
course_candidate:
  include: docs/学习地图/**/*.md
  exclude:
    - '**/index.md'
    - '**/roadmap.md'
    - '**/补充资源.md'
    - 'docs/学习地图/*课程表.md'
    - '**/数字后端.md'
```

### 改动

- 新增 `scripts/content_inventory.py`，输出确定性排序的 `docs/学习地图/内容状态.md` 和 `data/content_inventory.json`。
- 支持 `--check`：重新生成到内存并与跟踪文件比较；不同则退出 1，并提示运行更新命令。
- README 删除手写 85 条清单，改为链接到“内容状态”页；可保留一句不含硬编码数字的说明。
- `docs/学习地图/index.md` 删除重复清单，嵌入或链接同一生成页。
- “完全空白”改名为“暂无独立课程页”，并单独展示“已有替代资源”。

### 生成 JSON 最小字段

```json
{
  "generated_from_commit": "...",
  "definitions": {},
  "totals": {},
  "by_section": [],
  "skeleton_paths": [],
  "pending_paths": []
}
```

不要写生成时间戳，避免每次构建产生无意义 diff；使用源 commit 或完全确定性的内容。

### 测试

- 当前快照应产生：247 个可能课程、60 个骨架、11 个待建页、七个知识板块。
- 检查所有生成路径真实存在。
- 增删标记后单元测试中的计数同步变化。
- CI 运行 `python scripts/content_inventory.py --check`。

### 完成定义

README、学习地图总览和生成 JSON 不再有三套手工统计；新增或补完课程时只改课程页状态。

## PR 4：课程模板升级为“目标—资源—产出—验收”

### 新模板

保留现有 Markdown 可读性，在 front matter 增加最小稳定字段：

```yaml
---
page_type: course
course_id: mit-6-004
status: complete                 # complete | skeleton | pending | archived
suggested_window: core          # start | foundation | core | specialization | integration
domains: [digital, architecture]
prerequisites: [digital-logic]
public_access: true
last_verified: 2026-08-10
review_status: verified          # candidate | verified | stale
---
```

正文固定为：

1. 课程定位与适用人群。
2. 学习成果：3–5 条可观察行为。
3. 先修与衔接。
4. 资源表：主页、视频、章节、语言/字幕、时长、作业、最后核验日。
5. 学习产物与验收。
6. 同类替代资源和失效回退。

资源表最小结构：

```yaml
- role: primary
  title: ...
  provider: ...
  url: ...
  section: Lectures 1-12
  language: en
  subtitles: en
  duration_hours: 18
  has_assignments: true
  verified_on: 2026-08-10
```

### 渐进迁移

- 第一阶段只要求新建和被修改的课程页使用新模板。
- 现有页根据骨架标记推断 `status`，不一次性伪造未知字段。
- `last_verified` 缺失时显示“未核验”，不能默认今天。
- 校内不可公开资源明确 `public_access: false`，并为全国读者提供公开替代项。

### 校验

新增 `scripts/validate_content.py`：ID 唯一、状态合法、先修 ID 存在、日期合法、公开资源 URL 存在、主资源至少一项。迁移期对旧页发 warning，对新模板页严格报错。

### 完成定义

课程页能回答“为何学、何时学、学完能做什么、怎么证明、资源是否仍可用”，而不只是“课名 + 链接”。

## PR 5：科研方向置信度与证据元数据化

### 结构

每个方向页增加：

```yaml
---
page_type: research_direction
direction_id: analog-mixed-signal
route_id: analog-rf-bio
confidence: low
confidence_reason: 缺两名领域研究者审校；企业与课程前置待复核
review_status: needs_expert_review
reviewers: []
last_reviewed: 2026-08-10
evidence:
  - type: survey
    url: ...
---
```

### 规则

- `confidence` 不是作者自评分，而是证据与审校状态：
  - low：关键段落无一手证据，或没有领域审校人。
  - medium：主要事实有来源，一名领域审校人确认。
  - high：主要事实有来源，两名领域审校人确认，且 180 天内复核。
- 置信度下降自动发生：超过复核期限显示 stale，不继续保持绿色。
- 教授、企业、岗位和课程前置分别记录证据；一个公司官网不能支撑整页技术判断。

### 初始迁移

按 README 现有 8/4/5 分组写入 front matter，但 `confidence_reason` 必须明确标注“从 README 迁移，待领域审校”，不能把迁移本身当作新审校。

### 完成定义

- README 不再维护方向置信度清单；方向总览从 front matter 生成。
- 17 个方向全部有唯一 ID、六路线映射、状态、理由和复核日期。
- CI 检查 17 个方向无遗漏、无重复、全部被某条路线覆盖。

## PR 6：严格且可复现的 CI

### 工作流拆分

`quality` 先于 `deploy`：

1. 固定受支持的 Python 小版本。
2. 从锁文件安装 Python 依赖。
3. `python scripts/content_inventory.py --check`。
4. `python scripts/validate_content.py`。
5. `mkdocs build --strict` 到临时目录。
6. 检查站内链接、锚点和导航覆盖。
7. 使用 `package-lock.json` 中固定的 PageFind 版本建立索引。
8. `deploy` 只在 `quality` 成功后获得 `contents: write`。

### 依赖策略

- Python 依赖全部锁定直接与传递版本；不要混用固定版本和无上限范围。
- PageFind、Markmap 和 Mermaid 进入 `package.json` 并锁定，使用 `npm ci`；不再使用 `npx pagefind` 的隐式最新版或 CDN `@latest`。
- GitHub Actions 升级到实施时仍受支持的稳定 major，并固定 major；具体版本由 PR 当天官方文档确认，不在内容仓库中猜测未来版本。

### 外链策略

- PR 门禁：只检查内部路径、锚点、数据 ID 和少量官方主资源。
- 每周定时：检查全部外链，输出 artifact/Issue；对 403、429 和地区限制单独分类，不把一次网络波动当作删除依据。
- 主视频失效时必须已有备选，才允许把主资源标为 stale。

### 完成定义

- 任何生成物漂移、导航漏项、schema 错误或严格构建警告都会阻止部署。
- workflow 不含隐藏关键失败的 `|| true`。
- 只有部署 job 拥有写权限。

## PR 8：重复内容数据化与维护责任

### 数据拆分

```text
data/
  courses.yml
  directions.yml
  organizations.yml
  resources.yml
  routes.yml
```

- `directions.yml` 作为 17 个方向名称、路线归属、置信度和页面路径的单一真源。
- `organizations.yml` 存教授/企业官网、机构、关键词、方向映射、来源与核验日，替代 660 个手写 badge。
- `resources.yml` 存视频/课程主备关系和核验元数据。
- 生成脚本输出方向卡片、导航片段和统计；叙事正文仍留在 Markdown。

### 治理角色

- 为六条路线各指定至少一名内容 owner；用 CODEOWNERS 或文档化 reviewer matrix 表达。
- 增加 PR 模板：变更类型、事实来源、核验日期、是否改变导航/ID、版权确认、截图/构建结果。
- 低置信方向需要领域 reviewer；普通链接修复可由维护者直接合并。
- 90 天复查公开视频，180 天复查教授/企业/岗位类事实；过期只标 stale，不自动删除。

### 完成定义

新增一门课或一个方向关联只改一份数据，导航、总览、卡片和统计由生成器同步，不再要求贡献者同时理解 Markdown、SVG、JS 和 67 KB 的 MkDocs 配置。

## 推荐合并顺序

1. PR 1：hook 回归修复。
2. PR 2：移除行情与小时部署。
3. PR 3：生成内容状态，消除当前统计漂移。
4. PR 6：严格 CI，先建立迁移安全网。
5. PR 4：课程模板与渐进 schema。
6. PR 5：方向置信度和六路线映射。
7. PR 7：自由探索入口、筛选和无障碍。

## 回滚与兼容

- 数据化生成页面必须沿用现有路径；若路径必须变化，先加 redirect，再发布至少一个版本后移除旧内容。
- 新 schema 校验分两阶段：旧页 warning、新页 error；当迁移率达到 100% 再把所有 warning 升级为 error。
- PageFind 重构前保留现有搜索入口；新旧索引用固定查询集比较后再删除旧代码。
- 生成脚本输出确定性排序；若生成结果异常，只回滚生成提交，不回滚内容源数据。
