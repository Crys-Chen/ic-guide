# 维护手册

## 更新一种资源

1. 在对应视频 YAML 中修改记录，不直接编辑生成页面。
2. 打开链接，核对标题、教师、机构、章节、是否免费和是否仍可播放。
3. 更新 `checked_at`，重新评估匹配度、可信度、完整度、配套材料、稳定性与呈现质量。
4. 确认建议观看时长不超过该能力的参考投入，且不把“看完”写成完成标准。
5. 依次运行数据校验、页面生成、严格构建和链接检查。

## 失效链接处理

- 原机构改版：优先替换为同一课程的新官方地址。
- 视频下架但课程页仍在：保留课程页作为来源，将视频角色改由备选资源承担。
- 只有未经授权搬运：删除搬运链接，记录为资源缺口，不以低质量链接填空。
- 平台阻止自动探测：人工浏览核验并在链接报告中标注，不把 403 等同于内容失效。
- 多次重定向或循环：先替换为机构当前的最终稳定地址；不可稳定自动探测时标为 `browser_review` 并留下人工证据。

## 内容复核频率

- 视频和课程入口：每六个月复核一次。
- 教师、课题组、企业与岗位信息：每年复核一次。
- 培养方案：学校发布新版后复核。
- 核心数学、物理和电路内容：有事实错误或更优公开资源时更新，不追逐无意义的“最新”。

## 全量复核流程

```bash
python scripts/validate.py --strict
python scripts/render.py
python scripts/render.py --check
mkdocs build --strict
python scripts/check_site.py
python scripts/check_links.py --strict --report reports/link-check.json
```

1. 阅读脚本的计数与覆盖结果，不手工维护 README 中可能过时的数量。
2. 对 `link-check.json` 中的 `failed` 和 `browser_review` 逐条处理；只有严格检查返回 0 才可发布。
3. 六条路线各抽查至少两个能力，对照官方课程目录、建议 `section` 和学习成果，结果写入 `reports/content-spot-check.md`。
4. 在桌面和窄屏下实测首页、能力页、路线页、资源筛选页，并保存一份移动端验收记录。
5. 若能力 ID、课程或路线发生变化，同步更新 `course_mappings.yml`，再由生成器清理已不存在的生成页。

## 合并质量门槛

- 任何能力点必须有成果、验收产物、学时、合法先修关系和两项视频。
- 主资源总分至少 80，备选至少 70。
- 推荐理由必须解释“为什么适合这个能力点”，不能只复述课程标题。
- 能力依赖无环、路线引用、项目计时和课程映射必须通过机器校验。
- 不接受付费推广、破解资源、私有网盘教材或来源不明的课堂录像。
