# IC 自学指南现站全面审计

审计日期：2026-08-10  
上游快照：`ec90dfde5c36e89461386547903c7caaff107436`（2026-07-21）  
审计对象：[线上站点](https://crys-chen.github.io/ic-guide/) · [上游仓库](https://github.com/Crys-Chen/ic-guide)

## 结论摘要

现站已经是一份内容体量很大的“学科地图”：它用七个知识板块自底向上组织课程，又用 17 个科研方向自顶向下说明研究问题、课题组和去向。真正缺的不是再堆一批链接，而是把“资源目录”升级为“可以执行和验收的培养系统”。

最优先的四个问题是：

1. **没有面向自主探索的行动入口与学习验收。** 学生能看到学科树，却很难回答“我可以从哪个兴趣或项目开始、学到什么程度、用什么作品证明学会了”。
2. **统计与页面状态已经漂移。** README 声称“80 余个纯骨架页”，但按站内自己的精确标记只剩 60 个；README 的 85 条骨架清单中有 26 条已经不再是骨架，另有 1 个真实骨架未列出。
3. **资源缺少可维护的质量与时效字段。** 247 个“可能是课程”的页面中，没有页面显式记录资源最后核验日期；课程模板也没有学习成果、验收产物、视频评分或替代资源字段。
4. **构建链存在两个已证实缺陷。** `hooks.py` 的第二个 `on_post_build` 覆盖第一个，中文搜索索引修补不会执行；CI 又调用不存在的 `fetch_foreign_quotes.py` 并以 `|| true` 隐藏失败。

因此，本项目新增的自由探索路线、56 个能力点、六条方向路线和结构化视频数据，是对现站最关键的补层；不应复制现站的深层目录，而应把现有课程作为可按兴趣、项目和能力缺口检索的资源池。

## 审计口径与证据边界

- 精确统计来自审计时获取的上游只读快照；快照提交与日期见报告开头，审计前工作树为 clean。
- 线上核查首先依照 ego-browser 技能执行，但桥接约 60 秒没有返回页面状态或错误，随后终止悬挂会话。降级使用公开网页抓取，确认线上首页、五个顶级入口以及已发布的深层学习地图导航。
- 因浏览器桥接不可用，本报告**不声称**完成了移动端截图、真实点击搜索或焦点顺序的动态验收；体验结论同时以已发布页面结构和前端源码为证据。
- 审计环境没有 `mkdocs` 命令，因此未对上游快照运行 `mkdocs build --strict`。启发式相对 Markdown 链接检查覆盖全部 `docs/**/*.md`，未发现不存在的本地目标；这不能替代 MkDocs 严格构建和外部死链检查。
- 全量机器可读统计与页面清单见 `inventory.json`。

## 信息架构与当前精确库存

### 站点模型

现站的产品模型很清楚：

- 首页提出“让知识回归连续”和“让信息回归透明”，将学习地图称为自底向上的阶梯，将科研方向称为自顶向下的灯塔（`docs/index.md:69-71`）。
- 顶级信息架构为：首页、科研方向、学习地图、工程工具、专题社区；页头另有参与建设和后记。
- 学习地图按数学、物理、器件与工艺、电路、系统架构、算法编程、人工智能七个板块组织（`docs/学习地图/index.md:1-17`）。
- 17 个方向页全部有相同的六个二级章节：“研究什么、适合谁、学术界、毕业去向、相关科普、论文推荐”。这是现站最成熟、最容易复用的一套内容模板。

### “5 个空白分区”的准确解释

README 与学习地图总览列出的五个分区均没有子课程 Markdown：控制与机器人、生物电子、数字验证、功率电子、类脑与 SNN。

其中前四个确实只有领域说明和征集标准；“类脑与 SNN”页面已经收录 EPFL Neuronal Dynamics、snnTorch 和 Open Neuromorphic 三组替代资源，因此它是“无独立课程页”，不是“页面完全空白”。建议把栏目名改为“暂无完整课程页”，避免低估已有工作。

另外，站内 `# 〔待建〕` 标记共有 11 处，而非 5 处。多出的页面主要是已有复旦骨架课程、但仍缺公开完整课程的分类，如 MEMS、先进封装、功率半导体、电磁场、热统、模拟版图和数字后端。`# 〔待建〕` 与“完全空白”是两套不同概念，不能共用一个统计数字。

### 骨架统计漂移

可复现的差异如下：

- README 和学习地图总览都写“80 余个课程页是纯占位骨架”（`README.md:64-76`；`docs/学习地图/index.md:121-126`）。
- README 骨架折叠清单实际包含 85 个链接。
- 85 个链接中只有 59 个仍带标准骨架标记；26 个已经有实质内容但仍留在骨架清单。
- 当前 60 个真实标记骨架中，`系统架构/AI加速器/FDU_ICSE30034.md` 没有出现在 README 清单。

这不是文案小错，而是人工维护统计必然失真的例子。机器生成统计和 CI 一致性检查应成为上游首个内容治理修复。

### 科研方向置信度

README 将 17 个方向分成 8 个低、4 个中、5 个高置信度：

- 低：EDA、功率半导体、半导体器件与工艺、生物电子、量子计算、射频、模拟混合信号、MEMS。
- 中：具身智能、硬件安全、FPGA、类脑芯片。
- 高：先进封装、硅光、处理器架构、存算一体、AI 算法与系统。

该信息只存在于 README（`README.md:25-62`），方向页没有结构化 `confidence`、`review_status`、`last_reviewed` 或证据清单。每个方向页虽有 46–94 个外部 URL，但链接多不代表关键判断已经审校。置信度必须成为页面元数据，并明确“低”的原因：缺研究者审校、企业名单时效性、就业判断证据不足，还是课程前置尚未核验。

## 四维审计

### 1. 内容

**做得好的地方**

- 双向地图的概念准确，能同时服务“补基础”和“选方向”两类问题。
- 17 个方向页结构一致，既讲研究内容，也覆盖学术界、产业去向、科普和论文，广度明显超过普通课程目录。
- 七大板块的依赖图和数字 IC 流程图能建立宏观坐标。
- 对版权有明确提醒：非公开校内资源要征得老师同意，往年试题不公开传播（`docs/学习地图/index.md:19-25`）。

**主要缺口**

- 没有把兴趣、项目与能力缺口连接起来的行动路线，也缺少可观察成果和退出/转向提示。
- 课程页模板只有简介与资源，字段多数“按需填写”；缺学习成果、验收产物、阶段、方向、资源评分、字幕/语言、直接章节、最后核验日期和替代链接（`course_template.md:23-48`）。
- 资源链接的粒度不一致：有的到具体视频，有的只到课程主页或播放列表，无法统一比较。
- “复旦培养方案课程”与“全国学生可直接完成的公开资源”混在同一导航层，站外读者需要自行判断可访问性。
- 方向页写了大量教授、企业与股票行情，但与学生下一步行动的连接仍弱；缺一个最小先修集、方向体验项目和方向选择标准。

**对新增站点的要求**

- 现站课程页作为候选资源，不直接继承其“已验证”状态。
- 所有能力点必须有可观察成果和验收标准；视频只是达成成果的输入。
- 方向页转化为六条路线，每条只保留四个专业能力点、一个专项项目和清晰出口，避免学生被 17 个并列方向淹没。

### 2. 体验

**做得好的地方**

- 首页价值主张明确，并给出“探索科研方向”“学习地图”两个主入口。
- 顶部五类入口稳定；生产站使用 PageFind 搜索，源码支持点击、`/`、Ctrl/Cmd+K 和 Escape。
- 待建页在构建时生成灰显导航 CSS，能让用户感知内容状态。

**主要问题**

- 368 个 Markdown 导航路径形成很深的侧栏树。对熟悉课程名的人好用，对大一新生则缺少“从这里开始”。
- 没有按建议窗口、方向、语言、时长、来源类型、是否有作业筛选；搜索只能解决“知道关键词”，不能解决“还不知道该学什么”。
- 方向总览文件 1,551 行、173,605 字节，长叙事与导航地图混合；适合深读，不适合快速比较六条路线。
- 搜索 overlay 已有 `role=dialog`、`aria-modal` 与自动聚焦，但没有可见关闭按钮、焦点陷阱或关闭后焦点恢复；键盘和读屏体验未闭环（`docs/javascripts/search-pagefind.js:45-82,117-155`）。
- 两处 HTML 属性使用弯引号：`docs/index.md:81` 和 `docs/科研方向/index.md:162`，可能让横向滚动或 admonition 样式失效。

**改进方向**

- 默认入口改成“自由探索”；学习地图保留为“按领域查”，建议窗口只帮助判断大致先后，不规定年级。
- 资源索引用结构化数据生成过滤器和可复制的比较表。
- 方向对比页固定比较：对象、核心课程、典型任务、工具、项目、科研门槛、岗位；长文仍作为二级深读。
- 搜索对话框增加显式关闭按钮、焦点循环、关闭后返回触发按钮，并在本地开发模式提供可用搜索或明确构建命令。

### 3. 技术

#### 已证实缺陷 A：重复 hook 覆盖中文搜索处理

`hooks.py:143-158` 首先定义 `on_post_build` 修改 `search/search_index.json`；`hooks.py:209` 把它保存到 `_orig_on_post_build`；`hooks.py:212-214` 再次定义同名 hook，只调用 `_write_pending_css`，没有调用已保存函数。因此第一个 hook 不会从 MkDocs 入口执行。

生产页头明确写着“PageFind 搜索按钮（替代 Material 内置 lunr 搜索）”，CI 也在 MkDocs 后运行 PageFind。当前最小安全修复是让第二个 hook 调用 `_orig_on_post_build`，恢复作者显然想保留的行为；随后应决定是否彻底移除未使用的 Material 搜索链，避免双搜索架构长期并存。

#### 已证实缺陷 B：CI 引用缺失脚本

`.github/workflows/ci.yml:35` 运行：

```bash
python3 scripts/fetch_foreign_quotes.py site/quotes.json || true
```

仓库中没有该脚本，也没有跟踪的 `quotes.json`。方向页有 13 个 `yf:` 行情占位、涉及 11 个海外代码；它们只能进入 `stock-quote.js` 的“行情↗”回退。`|| true` 又让功能持续损坏而 CI 仍为绿色。

教育指南不应为了非核心股票行情每小时获得仓库写权限并重建整站。推荐直接移除海外行情生成、小时级 schedule、行情 span 和 `stock-quote.js`；企业名称继续链接官网即可。若维护者坚持保留，应补齐脚本、缓存和 schema 测试，并让失败在 CI 中可见。

#### 构建与供应链

- CI 运行 `mkdocs build`，没有 `--strict`。
- `actions/checkout@v2`、`actions/setup-python@v2`、`python-version: 3.x`、`npx pagefind`、`markmap-autoloader@latest` 和 `mermaid@11` 不能构成可复现构建。
- 依赖文件部分固定版本、部分只给下限或不固定；没有锁文件。
- 没有外链检查、导航覆盖检查、骨架统计检查、方向元数据检查和数据 schema 检查。

#### 负载与维护成本

- 首页的 `galton.gif` 为 6,847,500 字节，且位于首页内容中；`kilby.jpg` 为 2,561,596 字节。
- 全站 Markdown 内有 91 个内联 SVG；17 个方向页共出现 660 个机构 badge、164 个行情 span。
- `mkdocs.yml` 有 263 条手写重定向和 368 条导航路径；方向总览还内嵌大块 SVG。修改一个方向往往要同步 Markdown、总览 SVG、JS 和导航。

应把方向、教授/企业、课程、视频和状态迁移到数据文件，由生成脚本负责导航、卡片和统计；手写 Markdown 只保留叙事正文。

### 4. 治理

**现有基础**

- 有 MIT License，并注明部分课程页继承自北大 CS 自学指南。
- 有完整贡献指南和五个结构化 Issue 模板，覆盖新增条目、学习分区、笔记、论文和视频。
- 贡献指南要求使用官方主页/论文等事实来源、拒绝推广，并鼓励一类问题一个 PR。

**治理缺口**

- 没有 PR 模板、CODEOWNERS、内容审校人或分领域维护人。
- 课程模板没有要求来源核验日期；方向置信度也不是页面元数据。静态内容会随着教师、公司、课程和链接变化而悄然过期。
- README、学习地图总览和实际页面三处维护同一统计，已经出现可证实漂移。
- 新增课程要求手工更新父 `index.md` 与 `mkdocs.yml`；新增方向还要手工改总览 SVG 和 `orbit-galaxy.js`，贡献门槛高且容易漏改。
- CI 对预期失败使用 `|| true`，削弱绿色构建的可信度。

建议建立“数据所有者 + 审校状态 + 最后核验日期 + 自动过期提醒”的轻治理：低置信方向至少两名领域审校人签字，视频链接每 90 天自动抽查，课程与公司类事实每 180 天提示复核。

## 对本次独立站点实施的直接约束

1. 不把“有链接”当作“已培养”：每个能力点都必须有可提交产物和验收条件。
2. 不复刻上游统计：独立站点所有数量从 YAML 生成，并在构建时校验。
3. 不继承上游资源状态：所有 112 个主/备视频单独记录精确章节、评分和本次核验日期。
4. 不让 56 个能力点同时压给一个学生：默认路径固定为 32 个公共点加一条路线的 4 个专业点。
5. 保留上游优势：七板块作为领域索引，17 个方向映射到六条路线，长篇方向内容用作延伸阅读。
6. 明确来源关系：独立站点说明它基于公开上游做审计和补充，不代表上游维护者认可；不复制无必要的大段正文或受限资源。
